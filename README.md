# جدولي اليومي — Flutter

مشروع Flutter عربي خالص لإدارة المهام اليومية محليًا على Android. لا يستخدم `package.json` أو `npm` أو React Native. يترك `applicationId` واسم التطبيق والأيقونة في إعدادات Android قابلة للتعديل لاحقًا.

## الوظائف
- صفحة اليوم مباشرة مع انتقال بين الأيام وحفظ مستقل لكل يوم.
- مربعات مهام متعددة الأسطر، إضافة/تعديل/حذف، لون، وقت، تكرار يومي، وحالة (مكتملة/غير مكتملة/دون تحديد).
- ثلاثة أقسام قابلة للطي في أسفل الصفحة.
- SQLite محلي عبر `sqflite`.
- إشعارات Android محلية مجدولة عبر `flutter_local_notifications` مع طلب إذن Android 13+.
- واجهة RTL وإعدادات الإشعارات ومعلومات المطور.

## التشغيل في Klencode أو أي بيئة Flutter
1. افتح مجلد المشروع الذي يحتوي على `pubspec.yaml` مباشرة، وليس مجلدًا أبًا إضافيًا.
2. نفّذ `flutter pub get`.
3. نفّذ `flutter analyze`.
4. للبناء: `flutter build apk --release`.
5. الناتج المتوقع: `build/app/outputs/flutter-apk/app-release.apk`.

## التخصيص
- غيّر `android/app/build.gradle` لتعديل `applicationId`.
- غيّر `android/app/src/main/AndroidManifest.xml` لتعديل اسم التطبيق.
- استبدل أيقونة `mipmap` عبر أدوات Flutter/Android لاحقًا.

## ملاحظات مهمة
- بيئة التنفيذ التي أُنشئ فيها هذا الملف لم تكن تحتوي على Flutter أو Dart، لذلك لم يتم تشغيل `flutter pub get` أو `flutter analyze` أو `flutter build apk` هنا، ولا أدّعي نجاحها.
- لم تصلني سجلات المحادثات السابقة كاملة؛ المتاح فقط هو سجل React Native الذي يذكر فقدان `package.json` ورسالة عدم إنشاء Gradle output. سببها أن سير العمل كان يحاول بناء مشروع React Native/مسار غير صحيح، أما رسالة Gradle فنتيجة لاحقة لعدم اكتمال البناء. هذا المشروع لا يحتوي على `package.json` ولا يعتمد على npm.
- دقة الإشعارات ليست مضمونة في كل الحالات بسبب Doze وتوفير الطاقة وإعدادات الشركة المصنّعة؛ استخدم Android 13+ مع السماح بالإشعارات، وعلى Android 10 قد تؤخر قيود الطاقة التنبيه.
- زر التكرار ينشئ نسخة مستقلة للمهمة عند فتح يوم جديد بلا مهام، ولا يغيّر أي تعديل أو حالة في يوم حالة يوم آخر. إذا كان اليوم يحتوي على مهام يدوية، لا تُضاف نسخ تلقائية لتجنب التكرار غير المقصود.
